# claude-annotate

Run the tests with:

    uv run -q --with-requirements requirements-test.txt python -m pytest skills fleet/tests -q

`requirements-test.txt` pins the test tooling for the pre-push hook and this command alike: pytest, pytest-xdist and aiohttp. The suite runs about 2,700 tests (the fleet plugin's 200 included) in about 50 seconds, on 4 workers (`pytest.ini`). For one file, name it instead of `skills fleet/tests`. Add `-n 0` to run serially.

The suite has no browser tests and starts no daemon: no test drives Chromium, and none needs webcompanion running. Keep it that way. A few tests run the page's JavaScript under node and skip without it. `skills/stage/tests/stage_page.py` and `skills/talk/tests/call_page.py` run the real `stage.js` and the call page's scripts (`call.js` and the `call-*.js` files its HTML loads, in that order) under node on a small DOM (`skills/_shared/tests/dom_shim.mjs`), for page logic only: every box measures 0, so nothing about layout can be checked there.

A green suite does not show that the tests guard the code. `/audit-tests` (`tools/audit_tests.py`) plants small bugs in the lines changed since its last run and reports each one no test fails on, plus flaky tests and tests that run exactly the same lines as another. When planting a bug by hand to watch a new test fail, set `PYTHONDONTWRITEBYTECODE=1`: a file restored within the same second at the same size otherwise runs the planted bug again from Python's cache (`~/.cache/pycache`).

**Seeing a talk answer as a user sees it** is `tools/talk_render/` (outside the suite, like `tools/fleet_ui_e2e.py`): `uv run --with playwright python tools/talk_render/render.py --repo <checkout> --answer <file> --code <folder> --out <dir>` starts that checkout's talk server on a free port with a silent speech engine (no Azure, never port 8766 or launchd), plays the answer on a real call page and shots every board and point at 1440 px, 390 px and dark (`README.md` there). Use it to check a change to a board or the call page by eye. The bulldozer runs on talk and the stage, their workflows and their records are in `docs/bulldozer/` (`README.md` says how to run one).

The repo has no GitHub workflows, so nothing checks a push on GitHub. `.githooks/pre-push` is the only gate: it runs the suite with an empty `HOME` so no daemon config of yours is reachable, after compiling and collecting it under Python 3.9, and blocks the push if anything fails. It runs the full suite under one Python only. `/audit-failing-tests`, typed by hand, runs it under Python 3.9 and the newest Python in a clean worktree, then fixes and pushes what fails. A fresh clone enables it with:

    git config core.hooksPath .githooks

The stage's rules (`skills/stage/SKILL.md`, "What the stage keeps true") are checked on compiled frames by `stage_rule_breaks` in `skills/talk/tests/helpers.py`: call it on any reply a new test compiles. The scene compiler names what is being said in every frame (`cur`); the page draws that and never works it out itself. A saved scene from before `cur` is the one exception: `settled()` in `skills/stage/static/scene.js` gives its frames today's arrow rule as the view arrives, and `beingSaid()` guesses its part being said.

A board keeps one scene per answer that stepped it (`scenes`, keyed by the answer number as a string; `scene` is the one of the answer that last put the board up, absent when that answer had none). In `stage.js` read a view's scene through `sceneOf(v)` or `painted(v)`, never `v.body.scene`, so a replayed answer steps its own frames. Talk numbers an answer by the Claude entries before it, so a test that splits two replies must `call.add("claude", ...)` between them, or both get the same number.
How a board with no verbs is stepped (`scene.auto_steps`, `scene.said_parts`): a sentence names a part by more than half of the words of a label, or by a word of a label that no other part holds (`scene.distinctive`: the same word or a close form, a shared prefix of five letters, any alphabet; a short word counts only as the one word that tells the part apart). A part no sentence names is never lit by order: it comes in with the rest frame, `auto_steps` lists it, and `scene.unnamed_parts(model, sentences)` gives `{key, label, sentence}` for the `board:` line. Only a sequence's steps and a table's rows, which are ordered by nature, fill the sentences that name nothing, and no sentence that names a part is handed to another. A table of three rows or fewer is not stepped but `said_parts` lights the row a sentence names (by its first or any unique cell, never a column header; a text two rows share lights none). A column or row is read by its full text, then without a trailing parenthetical, then by a unique word or prefix with a `read as` note; a row range past the end of the table is cut at it, with a note. A sequence step's `ref` popup goes through `model.locate` like a code board, so `.env`, `.git` and ignored files are refused.

The stage demo's change board (`skills/talk/demo.md`, "Cells and the current one") points at line numbers of `skills/stage/static/scene.js` against an old revision. An edit to that file above those lines moves them: re-point the demo in the same change (`test_the_demos_change_board_points_at_the_lines_it_talks_about` in `skills/talk/tests/test_demo.py` fails until you do, and `/audit-demo` checks the rest).

The call page is one program in several classic scripts that share one global scope (`skills/talk/static/`, loaded by `call.html` in this order, which `skills/talk/tests/call_page.py` reads from the HTML): `call.js` (the core: `CFG`, `$`, `store`, `api`, popovers through `registerPop`, the toast, the shared state, `paintAll`, the poll), `call-calls.js` (the floor and the other calls), `call-wait.js` (the foot's status line, the voice being made, sending text, Undo, the wait card), `call-player.js` (the claim, autoplay, the queue, `load`, `playFrom`, `togglePlay`, `jump`), `call-stage.js` (the stage bridge, following, the reader, stops, the board following the voice), `call-shell.js` (the Now card, the earlier answers and the transport), `call-return.js` (the welcome-back card, the live region), `call-input.js` (settings, keys, the mic and recording), `call-live.js` (live mode) and `call-boot.js` (starts the page); `call-shell.css`, `call-wait.css`, `call-calls.css` and `call-input.css` follow `call.css`. Top-level statements run in file order, so a file never calls another file's function or reads its `let` or `const` while it loads, only inside functions and handlers. `paintAll()` calls one paint hook per feature (`paintNowCard`, `paintWait`, `paintEarlier`, `paintInputMode`, `paintStateStrip`, `paintWelcome`, `paintAnnounce`), the poll calls `waitOnView`, `callsOnView`, `returnOnView` and `shellOnView` with the view it replaces, and a sent turn calls `turnSent` (`skills/talk/tests/test_call_files.py` holds the file list, the slots in `call.html` and the rule that no name is declared twice).

On the call page every play the reader starts (Play, Space, a tapped word, an earlier answer's Play, a spoken "go on", the media keys) goes through `readerPlays()` in `skills/talk/static/call-stage.js`, which resends the whole picture and leaves following as it is: a board the reader picked stays in front. A new way to start playback must call it too; an automatic play (a new answer, a held answer picking up after the user spoke) must not, so its answer's `stage:answer` turns following back on. The card's own Play, Space and transport play the answer the card shows; only a stage the reader pinned by hand (following off) sends Play to the answer that owns the board in front (`boardStart()`, called only then, and the button says "Play answer N" in a word beside its icon). That play, Play from here on a step, and a play of another answer's row in the earlier list also call `followAgain()`. Otherwise following comes back with the Following strip's button, the stage's Follow the voice button, the gear's switch, or the next answer.
One page of a call speaks: the server holds the claim (`POST /api/player {page, take}`, `claim_player` in talk.py; `/api/state?page=<id>` keeps it and the state carries `player`), and a page plays by itself only when `player` is its own id. A page claims it when it opens, takes it when the user presses play (the page that held it pauses at its next poll), and another page of the same call says "Playing on another screen." and does not start a new answer. Only when the claim request fails (an older server) does the page fall back to `talk.playing.<call>` in localStorage (page id and time, renewed each second while it plays), which pages on other devices do not share. An audio file that cannot load shows "Cannot load the audio file" with a Retry in the toast; "The browser blocked playback" is shown only for a `NotAllowedError`. A phone gives the stage more height while a board is up (`data-board` on `.app`, `--ph` 38% instead of 46%). A new answer that arrives while another plays is queued (`queued` in `call-player.js`), shown as a row above the player with a Skip (`#queuerow`, `skipQueued` in `call-wait.js`), and starts when that one ends. The sentence runs of a page come from the answer's `starts` when it has them (`sentenceRuns`), else from the page's own splitter.

The other calls and the way back (`call-calls.js`, `call-return.js`): a call is said in one set of words, `callInfo(c)` for the others (from `Server.summary()`: `unheard`, `ended`, `stalled`, `working`, `floor`, `last_at`) and `hereInfo()` for this call, ranked by need (`CALL_NEED`: stalled, new answers, answering, playing, talking, waiting for you, ended; `NEEDS_YOU` is the first two), and `home.html` says the same words (`test_call_calls.py` holds the two together). The Calls popover (`paintCalls`) lists this call first and the others by need, with `Next waiting` (`nextWaiting`) and All calls in its foot; the Calls button (`paintCallsButton`) counts the calls that need the user. `paintCallsButton` runs on every tick of the audio and also repaints the popover rows, the tab (`paintTab`: title `<word> · topic`, `(n) New` for answers that came while the tab was out of sight (`unheardHere`, `shownUpto`), and an SVG disc as the icon) and the strip (`paintStateStrip`, one line, not a live region); each does nothing while its words are the same. When another call takes the voice (`yieldFloor`) the pause is `floorNote`, said in the strip with Resume here (`resumeHere`, a play the reader starts, so it goes through `readerPlays()`); the toast is only for the collapsed rail. A tab that leaves sight writes `talk.away.<call>` (`{at, upto}`); coming back after `AWAY_MIN_MS` sets `absence`, after `AWAY_MS` also opens the welcome-back card (`paintWelcome`), and `newAnswers()` are the answers after `upto` that are not heard. Play the new (`playTheNew`) plays them in order: the first through `readerPlays()`, the rest from the `ended` event by themselves (no `readerPlays()`), with an answer that arrives meanwhile held in `catchStash` until the list is played. `returnMarkEarlier(list)` puts `#sinceleft` before the first of them in `#tllist`. The one live region is `#announcer` through `announce(text)`: deduped for ten seconds, a burst said as one, spaced, held while the user types; `returnOnView` announces an answer arriving, Claude starting or changing step, a stall and an end, and `paintAnnounce` a board change while the voice is silent. `#reader` is `aria-hidden` (the panel holds its text) and `#skiplatest` jumps to the newest answer.

How the user talks and steers is `call-input.js` and `call-live.js`. The foot's switch `#modesw` is Type, Talk or Live (`inputMode`, set by `setInputMode()`, which maps it to the shared `talkMode`: `"live"` for Live, `"manual"` for Type and Talk; a switch kept by an earlier page is read from its stored `talkMode`). Type puts the mic away and the cursor in the field, and the switch is locked while recording. Live's two options (Interrupt, Send after a pause) are pills of the switch (`#bargepill`, `#pausepill`), not rows of the gear, and there is no header chip. `#yourturn` says whose turn it is from `yourTurnState()` (Your turn, Typing, Recording, Writing it out, Claude is working, Claude is speaking; in Live Listening, Hearing you, Muted, No sound heard, Live is off). In Live the mic button is a true mute (`setMuted`: the stream, the floor and this page's claim stay, nothing is sent and the speech in progress is dropped); a stream flat at zero for `LIVE.flatMs` is "No sound heard" (a track the browser muted says so at once), and the spoken commands `slower`, `faster` and `say that again slower` (`COMMANDS` in talk.py, `speedBySpeech`) move the voice speed one step. The voice speed is a chip in the player (`[data-speedchip]`, `cycleSpeed`) as well as in the gear, and Back is one sentence (`jump(-1)`), never a fixed ten seconds. The keys are one table, `KEYS`: the Keys sheet `#pKeys` (opened by `?` where nothing is typed, by the hint's Keys button or by the gear's row), the hint under the field and the tests all read it. Space, the arrows and `?` are plain keys; every other shortcut is an Alt chord read by `ev.code` (S speed, M message field, P player, V follow the voice, T talk), since a letter typed anywhere goes to the message field. Two skip links (`#skip`) are the first stops of the page. A layer (the gear, the Keys sheet, the Calls popover) takes the focus when it opens, keeps Tab inside, and gives the focus back to the button that opened it unless the user already went elsewhere (`popChanged`; `popButton` remembers the button per layer, and a layer opened from a row of another hands back to that one's button). Settings are in plain words: the voice is `engineText()` (no machine or profile), the language is "Speech language" with "Detect", the theme follows the system until one is picked, and End call stays at the foot of the gear (sticky). TV is `data-tv` on `.app` with one scale, `--tv`, which the panel's parts size themselves with (`calc(Npx * var(--tv))`): it is chosen in the gear, by `?screen=tv` or `?screen=desk` in the address (kept), and Full screen on a display 1700 px wide or more that has chosen nothing is TV size until full screen ends (`setScreen`, `tvByFullscreen`). On a phone or a coarse pointer every target is 44 px (40 for chips and text buttons), the key hint is not shown, and the mode switch shows its word only on the mode that is on; the panel is 58% of the height, 52% while a board is up.

A page is a board of an answer when the answer brings it in with `[[show page: <file in --code, address or session:kind/slug> | Title]]`: it gets a chip and a front cue like any board. A page put up with `stage.py show` during a call opens behind and has no cue, so the voice can never front it; `stage.show` with an owner replaces such a hand-put copy of the same page.

A scene (`[[show scene | T]]` HTML `[[/show]]`) is an answer's own page, revealed part by part: `model.scene_source` reads its `data-part` elements (refusing scripts, handlers and `javascript:` links), `scene.parts_model` makes them keys (`part:<id>`), and the stage keys them for `applyFrame` after DOMPurify (`paintScene`). With no verbs a scene still steps: `auto_steps` steps any scene of two or more parts, and a part no sentence names rides in with its parent. An answer with a front cue is "staged": the call page sends each sentence as `stage:caption`, which the stage shows as a bubble under the scene part being said, else as a bar. Design: `docs/superpowers/specs/2026-10-13-talk-answers-are-scenes-design.md`.

The call page reads every answer on the stage (`paintReader` in `call-stage.js`, `#reader` over the stage frame): each sentence appears as it is said and the word being said is lit (`now-word`), a tap on a word plays from there. When the voice reaches a board's front cue the board takes the stage and the reader becomes one strip under it with the sentence being said (`reader strip`); at rest an answer with a board shows the board, and a board the reader picked by hand (following off) stays in front. An answer with no front cue of its own leaves the board in front where it is (`keeps` in `paintReader`: the reader is the strip under it); it covers the stage in large type, under an `.rhead` that names its answer, only when the stage has no board in front. The stage gets no caption any more.

The panel is the Now card over a list of earlier answers (`skills/talk/static/call-shell.js`): no answer folds to one line, and nothing is a row except an answer. `turnsOf(view.entries)` pairs each Claude answer with the question that asked it: it keeps the questions asked since the last answer as a list, a normal answer takes the last and shows the others it was merged with (`also`), and a reply kept as superseded takes the question the correction names (`replaces`), else the first one the server set aside, and for an addition the first one asked, leaving the later question for the answer that follows. It also pairs the boards it showed (the `board` entries before it, which carry its `answer` number) and the notes it saved; `status` entries (progress notes) are not drawn at all, the foot says what Claude is doing. `paintNowCard` shows the answer in the player, else the newest (`shownAnswer`): `#nowstate` (icon and word from `nowState`), `#nownum`, the question `#nowq` (as typed, `pre-wrap`, three lines then Show all), the full text in `#nowtext` (a fade at the top or bottom edge says more lies there, and an answer played to its end scrolls back to its first line) with the word being said lit (`highlight`, `readSpans`; a tap on a word plays from there), `#nowchips` (`buildChip`: the Key points chip is named "Key points" with a "N new" badge, never "+N"; a chip's `aria-pressed` follows the board in front), the player in `#nowtransport` (previous and next sentence through `jump`, `#playpause`, a labelled `#seek`, `#time`, `#speedchip` through `setSpeed`; Play says "Play answer N" in a word beside its icon only when the stage is pinned and `boardStart()` would start another answer than the card's), a Copy answer button in the card's head (`#nowcopy`, which says Copied on itself and in the live region) and the Following strip `#nowfollow` (`paintFollow`, never clamped: "Following the voice" with "Stage still shows <board> from answer N" when the shown answer has no board, or "You chose this" with "Stage shows <board> from answer N. The voice is on answer M." and which answer Play starts, and one button: "Keep this board" (`pinBoard`) or "Back to the voice" (`followAgain` with `resync`)). A note the user asked to be kept is a row with a check and the word Saved, whole on as many lines as it needs, and links to nothing. Times go through `clockOf`: "Yesterday 09:05" or "24 Nov 09:05" when the entry is not from today While `waitActive()` the card shows the wait card instead of the answer. `paintEarlier` keeps one keyed row (`.tlrow[data-id]`) for every answer but the card's, on one grid (number, question and gist, boards, time, Play; a phone drops gist and time): a row opens in place (`opened`), Expand all opens every row, and the search (`#tlsearch`, `foldCached` compares without case or accents, `marked` marks the match with nodes, never markup) looks through every answer, the card's too, and through what each board shows (`search` on a board entry, from `board_text` in `talk.py`: a table's cells, a chart's labels and values, a diagram's step names, at most `BOARD_TEXT_MAX` characters; a hit shows "in <board>:" with the board's icon). While a query filters the list the count line says "Filtered: N of M answers" with Show all, and a question sent or a new answer clears the query (opening a row keeps it). Expand all brings the list's head to the top of the panel, the card's text window is shorter while earlier answers exist (`.convo.has-earlier`), and a fade over the foot of the panel says more lies below (`#convofade`). After a play from a row, focus goes to the player's button, or to the row's own Play when the row stayed. `returnMarkEarlier(#tllist)` puts the since-you-left divider in after the rows. A new answer or a question just sent brings the card back into view (`shellOnView`). The reader is still the stage's own text: it and the card read the same `sentenceRuns`.

A play of another answer's row (`playAnswer`) calls `followAgain()`, since the reader chose that answer's boards; the card's own Play, a tapped word and the keys leave a pinned board where it is, and the strip says so. A board the stage fronts is said to a screen reader through `announce` (`stage:shown`, `pinBoard`, `chipTap`). Scenes and stops are retired from talk's guide (`skills/talk/SKILL.md`, "No scenes and no stops") and from the demo; their code still runs for saved boards and for a session that writes the tags.
Round 2 of the bulldozer on talk (25 November 2026): `Server.stamp` carries `stalled`, so a polling page gets the "Claude has not picked this up" warning, and a turn collected but never answered with no doorbell back becomes stalled after `STALLED_OPEN_AFTER` (`view()` also says `listening`, a doorbell waiting). A call's stage that webcompanion finished by idle expiry is unfinished and the board shown once more (`show_reviving`), and the call page's state poll touches the stage every `STAGE_TOUCH_S`. A sentence ends after a Greek question mark (`;` before a Greek letter, or U+037E) in `sentence_starts` and in `sentenceRuns` alike (`test_r2_talk_core.py` runs both on the same inputs). `Board` remembers this reply's refused boards (`refused`, `last_refused`): a point or verb naming one, or naming none while the latest board was refused, is dropped with one `board:` line and never lights an earlier board. A bare code path (or `path:N`) shows the file from line 1 to `MAX_LINES` and notes only a cut. `point_for("outcome:end")` is `[[point: outcome]]`, and the by-order `board:` line lists each unnamed part by label with the sentence it came in with. `check_shape` adds two nudges, `MAX_KEY_POINTS` and `MAX_TITLE_WORDS`, that never drop a board.

A scene is written as a slide (`<div class="slide">` with a `kicker` and an `h1.title` that states the claim) built from forms in `stage.css`: `flow` and `vs` of `node`s (the arrow or "vs" is the `::before` of each node after the first, shown only with both ends), `stack` of `layer`s, `tiles`, `hero`/`num`, `callout`, `chip`, `tag`, with `data-tone` blue, red, green or amber. A top-level card not said yet is a dashed slot with no words; a part inside a part is `display:none` until said and rises in on a forward step (`s-play`). With no pointed focus, `s-on` dims the parts shown before the one being said. On a slide the caption is a bar across the foot (`caption bar sub`), never a bubble. `model.scene_warnings` turns a part over 16 words, or a scene with no slide, into a `board:` line; it never refuses a scene.

A stop (`[[check]]`, `[[guess: q | a | *b]]`, `[[say back: q]]`, `[[deeper]]`) is a cue `{at, kind: "stop", stop}` with no view: `talk.parse_stop` reads it, its question is put into the spoken text with the cue after it, and no stop question names a scene part (`compile_scenes` blanks them, so a guess never gives its answer away). On the call page `checkStop` pauses the voice at `stopTime` (just after the question's last word), `stopped` holds the stop it waits at, and `heldAt` keeps the stage from running past a stop not yet passed. `stopped` is set before the pause, since a pause paints the stage. The card is on the stage (`stage:stop`, answered with `stage:pick`) for a staged answer, else in the panel (`#stopcard`). A guess pick goes to `/api/pick` and rides on the next turn as `picks`; a say back answer carries `answering`. Design: `docs/superpowers/specs/2026-10-13-talk-stops-asks-and-sandbox-design.md`.

On a scene the stage takes questions (`tapScene` in `stage.js`): a tap on a part shown opens its popup (`.spop`) with Ask about this, which posts `stage:ask` so the call page pauses and starts the text field with `About "<part>": ` (`askAbout`), and Play from here (`playKey`, which also serves a sequence step). A `<dfn title>` shows its meaning, and `captionWords` makes the same term tappable in the caption.

A scene with a `<script>` or an `on…` handler is `sandboxed` (`model.scene_source`; a `javascript:` link is still refused, and script or style text names no part). The stage runs it in `<iframe sandbox="allow-scripts">` with no same origin and a policy of `default-src 'none'` (`paintSandbox`): the stage's stylesheet goes in inline and its fonts as `data:` URLs, since the frame's opaque origin cannot fetch them. `SANDBOX_SHIM`, put in first, keys its parts and applies the `scene:frame` messages `paintFrame` posts (show, focus, cur); it says `scene:ready` and gets the last frame again. Its caption is a bar, and it has no part popup.

The stage draws no Mermaid, and nothing vendors it. A Mermaid body is turned into a JSON spec before it reaches the page: `model.mermaid_source` for `stage.py show diagram:-` (a graph or state diagram becomes a flowchart, a `sequenceDiagram` a sequence) and `Board.from_mermaid` in `talk.py` for a call (a graph or state diagram only). A view of format `diagram` saved before that shows its source (`renderInline` in `stage.js`).

A before/after sequence (`compare: {before, after}`) is two lane boards side by side, never one merged diagram. `skills/stage/compare.py` lines the sides up like a split diff: it pairs steps (by id, else label and arrow), and its spec has one step per row holding the `before` and `after` step, with a gap where a side has none. `renderCompare` in `lanes.js` draws each side as its own lanes board from that row list (`sideSpec`), keyed by the row so a frame lights both, and `syncSides` gives each row the taller side's height so the two stay level. Design: `docs/superpowers/specs/2026-11-10-side-by-side-sequence-compare-design.md`.

The map (`skills/stage/static/map.js`) places its parts once per board size, with room round each for the larger card it becomes when said, and picks its layout (`data-layout`: `across`, as large as the pane lets it be up to 1.8 times, else `down`) by what fits. When the card being said changes, only the arrows and labels are redrawn. Where an arrow runs is decided by `skills/stage/static/route.js` (pure, run under node by `skills/stage/tests/test_map_route.py`): orthogonal, in the free corridor of every column it crosses, on a lane of its own in each gap, round the parts for a way back; a label sits on its own arrow, off it with a leader only when no stretch has room (`placeLabels` measures and draws; where each goes is decided by `skills/stage/static/map_labels.js`, pure, run under node by `test_map_labels.py`: never on a part, another label, another arrow or another arrow's head if any place avoids it). Two to four arrows into one part fan their heads in at least 12 px apart (`PORT` 18 in `route.js`). A part is at least as wide as its longest word (`wordNeed`: measured as a copy at its minimum content width, so no word of a name breaks in the middle), and a board taller than its pane is scaled down to the pane when it rests, down to half its size (`fitScale`; a taller one keeps its own size and scrolls), and is at its own size while a part is said. The board is pinned to the top of its pane and sized to the pane less everything else in it, so the parts do not move between frames.

An architecture map on the stage (`[[show map | T]]`, `stage.py show map:-`) is drawn on the server: `model.visual_source` runs `map_svg.render(spec, uid, keyed=True)` and keeps the SVG as the source's `svg`, since the map is measured and routed in Python. The page puts it in through DOMPurify's SVG profile (`paintVzMap` in `stage.js`), styled by `vz.css`. Its keys (`scene.map_model`) are `box:<id>`, `zone:<i>`, `edge:<from>-><to>#<n>` for a structure arrow and `route:<r>` for a step of its route; `layoutVzMap` puts the map in route mode while a frame before the rest shows a route step. With no verbs a map follows its route only when a sentence or a point names a step of it (`auto_steps`), and `[[all]]` never starts the route.

A bars board (`[[show bars | T]]`, `stage.py show bars:-`; `chart` is its alias) and a graph board (`[[show graph | T]]`, `graph:-`; Mermaid under `graph` is still read as a diagram) are drawn on the server like the map: `model.visual_source` runs `bars_svg.render` or `graph_svg.render` (`DRAWN` in `skills/stage/model.py`, keyed) and keeps the SVG as the source's `svg`; the page puts it in through DOMPurify (`paintVzMap`, class `vzbars` or `vzgraph`), styled by `vz.css` and `stage.css`. Keys: `bar:<id>` (`scene.bars_model`; `[[point: bar X]]`, `rows A-B`), and for a graph `node:<id>`, `edge:<a>-><b>#<n>` and, when some node is not `same`, `mode:before|after|both` (`scene.graph_model`). A graph with a before and an after draws both frames in one SVG, before above after, and carries a viewBox for each (`data-vb-before`, `-after`, `-both`): `layoutGraph` in `stage.js` dims the frame the voice does not point at. The SVG holds the graph drawn a second time turned (`<g data-orient="tall">`, `graph_svg._frame_tall`, viewBoxes `data-vb-tall-*`): lanes are columns, time runs down, names wrap and the text is 12 px and 11 px (vz.css), so on a board narrower than 640 px the page shows it (`svg.tall`) at a scale of 1 or more, before above after, panning down only and with the pointed frame brought into view. A saved graph without that drawing keeps one frame at a time through its viewBox with a Before / After switch; `svg.vzg` clips to its viewBox, since `svg.vz` is `overflow: visible`. A map on a phone is fitted whole to the pane's width (no sideways scroll, its small text is the price); an arrow lit on a map or flowchart is kept in view with the two parts it joins (`withEnds` in `stage.js`, the end of `layoutMap` in `map.js`). A table column is never narrower than its longest word (`wordFloors` in `stage.js` measures it in the cell's font as `--min` on the `col`, sets the text down to 72 % when the floors do not fit, then lets the table scroll; `columnWidths` in `skills/stage/static/fit.js`, pure and run under node by `test_s_fixes.py`, turns the shares and floors into px set as each `col`'s `style.width`, because Chromium reads `width: max(40%, 97px)` on a `<col>` as `auto` and the floor never held, which drew the first column under its own words) and cells never break a word. A board whose words are Greek has `lang="el"` on its pane (`langOf`), so a capital loses its tonos and Greek heads are not tracked wide; a bars board writes its numbers with a decimal comma when its words are Greek (`bars_svg._decimal`, or `decimal` in the spec) and says `1 day`, not `1 days` (`_unit_for`). The stage's `100vh` units are divided by `--z`, the `stage:zoom` the page sets on `<html>` with `zoom`, so a TV's zoom does not make the stage taller than the window. The step control of a scene (`.vstep`) is a button between two chevrons that have names: it steps on, and from All shown starts again; a code board is wrapped until the reader turns it off and an unwrapped one fades at its right edge while it holds more (`codeCue`); a slide at rest scrolls back to its title (`toTop`) and `centreTarget` (`fit.js`) never leaves its title half cut by the pane's edge; the board list (`.tabbar`) stacks above the sticky lanes header; no lanes rect is drawn with a negative width. `talk.check_table` adds a `board:` line for a cell word over `TABLE_WORD_MAX` (22) characters, the length the stage gives a column's floor, and the guide says a table the user named is drawn as named, up to 8 rows by 6 columns. On a phone a table whose columns do not fit (`data-fit="scroll"`) is never a sideways strip with cells cut at its edge: each row is a card, its cells whole, each labelled with its column's name (`data-label`); a table that fits is a compact grid. `pulseDiff` diffs a table's rows by text, not by place, so only an added or edited row glows. The stage header names a bars board "Comparison chart" and a graph board "Graph". The 390 px check for graph, map and table is the run's harness `phone_fit_r2b4.py` (browser only, outside the suite). `map_svg.validate` bounds a map (`MAX_COLS` 12, `MAX_ROWS` 40, `MAX_BOXES` 60, `MAX_ARROWS` 120) and names the field it refuses. `skills/_shared/visuals/label_check.py` is the one check of a board's words (a label 60 characters, a sub or a line 120, a spec 80,000 characters as JSON), called by `map_svg.validate` and, for the stage only, by `model.visual_source` for a flowchart and a sequence (annotate's stored specs keep drawing). A map is drawn at the widest tuning that fits `TARGET_W` 1150 px (`TUNES`: its lines, names and column titles wrap sooner, its boxes narrow), and one still wider carries, on the stage (`floor`), a rule inside its svg that scrolls it sideways below 11 px text on a screen wider than 760 px. An arrow whose single-gap routes are all blocked is routed by a search along the lines between the boxes (`_grid_route`: fewest turns and crossings, 6 px off every box and caption), and `render(..., report={})` hands back the boxes, routes, labels and captions for the tests. A bars note is refused by its measured width against the canvas (`bar 'a': note is 541 px wide on a canvas with 520 px of room`). A near-miss id in a point is read as the nearest one with a `board:` line (`Board.point_drawn`); both specs are refused with a `board:` line that names the id (zero or negative on a log scale, mixed units, a duplicate id, an edge to nothing, a cycle). The guide a session reads is `skills/talk/SKILL.md` (a short core: the decision table by question with the table last, the turn loop and one example each of map, wait, compare, bars, graph and flowchart) and `skills/talk/references/` (`boards.md`, `call-page.md`, `server.md`); `skills/talk/tests/test_demo.py` checks that the decision table comes before the board table, that every table of the guide has the same cells in every row, that the references are linked, and that every example parses against the real validators.

The lanes (`skills/stage/static/lanes.js`) are drawn in the look of `sequence_svg` (four tones, actor heads with their role, a chip on each call, check badges, phases as bands, an outcome box, one renderer for a plain and a compared board: a compared board draws it once under both sides), but stay HTML laid out in the page: they fit any board width, wrap and measure their words, and keep the popups, folding, following an actor and activation bars that `sequence_svg` does not draw. A look changed in one should be changed in the other. They draw a sequence whole, the steps not said yet faint, and draw the board again after every frame: `paint()` rebuilds the rows and gives each keyed element back the classes the frame set (`k-hidden`, `k-focus`), so a class put on a row from outside does not survive the next frame. On a phone five actors or more are cards marked with a letter (`actorMarks`: only steps are numbered) over a key (`ln-dense`, `columns()`; a compare board's two sides are dense together, `peers`); a call to itself on a narrow board has its chip over the loop and its note under it, and a step number sits at left 4 px on a narrow board and 20 px on a wide one; a frame's view goes to the step said on a row's edge (`follow`), to the top at rest and to the outcome when it is said (`st.aim`, `land`; a compare board's panes are `managed` and `landCompare` lands the side on show). Each step is one keyed row (`step:<id>`) holding its own arrow, so the scene engine still shows and lights it as one element. Lifelines, boxes (`groups`) and activation bars (from a call to its `reply_to`) are drawn under the rows in one SVG. The outcome box is the scene's key `outcome:end` (`scene.OUTCOME`) in a plain and a compared board alike, ghosted until said and lit at rest (`.ln-outcome.k-hidden` is `!important` because `.k-hidden` hides at opacity 0); a step's note is reserved room in the right margin (`columns()` measures the longest) and, on a phone, a line under the arrow of the step said; a compare point on a moved step lights both rows (`mate` in `sideSpec`) and a gutter connector. A row whose words wrap is measured and the board drawn once more (`measure()`); under the node harness nothing measures, so rows keep their base sizes there. A step's popup reads its source lines from the view's `refs`, which `model.step_refs` reads from the code folder when the board is made (talk's `Board.add_refs`, or `stage.py show sequence:-`); Play from here posts `stage:play` and the call page plays from that frame's cue through `playFrom()`, which follows the voice again with `followAgain()`.

A `map` or `sequence` part on the annotate page is stored as the vz player fragment (`render.py`, `visuals/player.py`), drawn at its own size with its title band cut off because the part's heading carries the title; `script-blocks.js` boots the players on every `annotate:rendered`, and Share puts each drawing back to the whole picture with no controls.

The annotate page never shows a block: a block renders as part of one document (`createBlockSection`), an authored title is an `h2` (`visibleTitle`), folding goes by heading (`fold-groups.js`), and every comment opens in the one floating window (`comment-window.js`). Text the reader sees says "part", never "section" or "block".

The `fleet` plugin (`fleet/`, a third plugin in the marketplace with `source: "./fleet"`) is separate from the other two: its own `plugin.json`, its own `hooks/hooks.json` and nothing imported from `skills/`. `fleet/fleet.py` is a stdlib-only CLI for Python 3.9+ that joins Claude Code sessions into a fleet and posts messages straight into a member's inbox socket (the `CLAUDE_CODE_MESSAGING_SOCKET` the member exported, stored at join), with no model on the sending side. Design and plan: `docs/superpowers/specs/2026-11-13-fleet-plugin-design.md` and `docs/superpowers/plans/2026-11-13-fleet-plugin.md`. The store is `$FLEET_HOME` (default `~/.claude/fleet`, made 0700; `fleet.db`, `ui.json` and `hooks.log` are 0600, tightened on open if looser) `/fleet.db`; tests set `FLEET_HOME` and `FLEET_SESSIONS_DIR` to temp dirs and never read the real sessions dir, using real sleeping processes as fake sessions and listener threads as fake inboxes, and one fake `claude` (`install_claude_stub`: `agents --json` lists the fake sessions, `--bg`, `stop`, `rm` and the headless `-p` answer) as `FLEET_CLAUDE_BIN` (`fleet/tests/fleet_testkit.py`; no `conftest.py` there, since the repo's other `tests` folders are packages). The repo is public: no machine, host or company names in the fleet code, tests or docs. A session that skips permissions holds inbound messages unless `crossSessionInbound` is `accept`; `fleet spawn` and `respawn` start sessions with it set, and `fleet join` checks nothing about settings (it read undocumented settings files and misjudged them). **One trust domain.** Every member can tell every other member to act, as the user would, so a member that reads untrusted text (a web page, a mail, a log, another repository's files) can be talked into telling the rest. Join only sessions you would trust with each other's tools, and treat what a member relays from outside as untrusted data; the wrapper's text is escaped (`<`, `>` and `&` in a body become `&lt;`, `&gt;`, `&amp;`) so a body cannot close the `cross-session-message` tag and forge a sender, but nothing stops a member from saying it. The hooks act only when `FLEET_JOIN_NAME` is set (SessionStart) or a store exists (SessionEnd). Across machines (`$FLEET_HOME/machines.json`, slice 3) every remote verb is `ssh <host> <python> <fleet.py> <verb>`; a message is stored on the target's machine by the internal verbs `_deliver` and `_answer` (JSON on stdin), a thread id is `t` plus hex (never all digits, which `thread` would read as a message id), and the tests put a fake `ssh` on `PATH` that runs the CLI with another `FLEET_HOME` per host (`World.host`, `World.link` in `fleet_testkit.py`). Without the cookie, `/` is a sign-in form that posts `password` to `/login`, which sets the same cookie (a wrong one waits a second and shows the form again). The server reads the token once at start; restart it after changing `ui.json`. Each request closes the store connections it opened (`db_scope`), a handler socket times out after 30 s, and `test_serving_many_requests_leaves_the_open_descriptor_count_flat` holds the descriptor count flat: without that the long-running service ran out of descriptors (`Errno 24`) because connections waited for the garbage collector. **The fleet stores nothing about what a member is doing (14 November 2026).** A five-voter design panel agreed on it, and Petros's rule is that the fleet is never inconsistent. So what a member is doing is worked out each time it is read, by `local_members` in one read transaction: `activity` is the raw `status` of `claude agents --json` (else its `state`; `unknown` when the command does not answer), `held` its claimed to-dos, `unanswered` the asks and tells to its session not yet answered, `free` only when it is idle and owes nothing, and `as_of` the read time on that machine. `fleet ls --state` prints it per machine, and the page's Members rows show it. Tested on 14 November 2026 with scratch background sessions: a permission prompt shows `status: waiting` with `state: blocked`, a finished turn `done`/`idle`, and a `blocked` entry with no pid is a stopped job. So no hook writes "waits for you". `test_nothing_about_a_members_activity_is_written_to_the_store` holds that. A member named `job:...` is skipped by a `*` broadcast (`is_job`), which says whom it skipped. A message carries its whole text into the receiver's conversation up to `WAKE_MAX` (2,000 characters; the same test got 2,000 through the socket whole), else it is cut there with `fleet thread <thread>`; `PREVIEW` (300) is only for list lines. To-dos have `owner` and `after` (`todo add --owner --after`, `todo set`): every change is one `BEGIN IMMEDIATE` (`in_write`) that refuses an unknown id, a to-do waiting on itself and a loop (`check_order`), and `claim` and `todo spawn` check the order and owner inside the same write; `waits_on`, `ready` and `owner_gone` are worked out on read (`todo_rows`). An order spans one store: `--after 3@bee` is refused. Lungo's needs-you items are read live, never stored: `$FLEET_HOME/lungo.json` (`{"command": [...], "ttl": 60}`, machine-specific, never in the repo) names the command that prints Lungo's brief (`lungo.brief/1`); `lungo_items` takes the first `counts.needs_petros` rows of `jobs` and refuses a brief of another shape. `fleet inbox` and For you list them as read-only `lungo:<machine>/<job>#<item id>` items with the time Lungo wrote them, `answer` and `dismiss` refuse them, an unreachable or changed Lungo is said ("Lungo: unreachable (...)"), never shown as nothing, and only the asking machine reads it (a fan-out asks `--local`). Tests: `test_fleet_live_state.py`, `test_fleet_todo_order.py`, `test_fleet_lungo.py`; the stub `claude` takes a session's status from `$STUB_DIR/status.json`.

**Block kinds live in one registry (`skills/annotate/static/block-kinds.json`).** Python reads it through `skills/annotate/kinds.py` (`KINDS`, `RETIRED`, `trait`, `with_trait`); `entry.js` fetches it and `static/kinds.js` gives the page `AnnotateKinds.is(kind, trait)`. A turn has a life the page shows and the user can steer (`skills/talk/static/call-wait.js`, `live_turns.py`, `talk.py`). `TurnQueue` tells a turn's state (`state_of`: `pending`, `open`, `folded`, `cancelled`, `superseded`, `answered`; a turn merged into a newer one before any doorbell took it is found through `alias`/`resolve`), and `Call.turn_of` maps each `you` entry to its turn, so `Call.turn_state(entry)` is `sent`, `picked` or none and `view.turn` carries `entries: [{id, state}]` (the questions in flight), `earlier` (replaced turns the session still holds), `collected_at` and `alive_at` (wall seconds).
