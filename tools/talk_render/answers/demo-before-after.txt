A before and after sequence puts the two flows side by side, row for row, so you compare their shape instead of working it out yourself. [[point: before]] On master, the proposal report asks for the forecast. The report service asks the Service client in Cart's module for the forecast data. The client builds the requests with fixed lists, always quarterly. It asks Service for the ex-post measures. Then it requests the forecast series. And it returns report timeseries. [[point: after]] With the PR, a shared forecast module takes the client's place. The service passes quarterly and its own measures down. The module builds the requests with the lists it is given, and returns raw values. The report service builds the report timeseries itself, the one row the old flow has no step for. [[point: both]] The Service requests are the same on both sides. [[key: a before and after board sets the two flows side by side, with a gap where one has no step]] Next is a map.
