# App map implementation plan

> **For agentic workers:** two batch jobs run in parallel, one per area: Batch P (Python, the skill and the build) and Batch J (Java, the IntelliJ part). Each works in its own worktree, writes all its code, runs its tests once, and commits. Steps use checkbox (`- [ ]`) syntax.

**Goal:** One key in IntelliJ (`alt M`) shows a prebuilt map of the application over the IDE with the open file's part lit; `/app-map` builds that map.

**Architecture:** `/app-map` (Python, stdlib) gathers facts, checks Claude's `source.json`, lays it out with `map_svg`, turns the SVG into a list of shapes and writes `map.json`. The plugin reads `map.json`, matches the open file with CODEOWNERS-style rules and paints the shapes with Java2D in an overlay on the IDE window.

**Tech stack:** Python 3.9+ stdlib; Java 25 IntelliJ plugin (`ide-plugin/`, Gson, JUnit 5).

**Spec:** `docs/superpowers/specs/2026-11-23-app-map-design.md` (read it whole, including "Settled after the builder check").

## Global constraints

- Nothing about any real project, host or company in code, tests or docs. Tests use the made-up `acme/shop` project.
- Python: stdlib only, runs on 3.9. Java: logic classes have no IntelliJ imports.
- Map files live in `~/.config/claude-annotate/app-map/<name>/`; `APP_MAP_HOME` moves the root. Tests always set it to a temp folder.
- Fonts in Swing are sized with `JBUI.Fonts.label(float)`, never `deriveFont`.
- Every new shortcut is in `ShortcutCatalog`.
- Commit messages are one line, no body, no trailers.

## Shared contracts (already written, do not change without changing both sides)

- `skills/app_map/tests/match_cases.json`: path patterns. `cases` (pattern, path, match) and `last_match_wins` (rules, path, winner index or null). A reference regex translation that passes every case: anchored when the pattern starts with `/` or has a `/` before its end; a trailing `/` means "folder: something must follow"; a last segment of exactly `*` means "no deeper"; otherwise the pattern may also name a folder above the file. `**/` → any folders or none, a final `/**` → everything below, `**` → `.*`, `*` → `[^/]*`, `?` → `[^/]`.
- `skills/app_map/tests/sample_map.json`: the exact `map.json` format the build writes and the plugin reads. Shape kinds `rect`, `path`, `circle`, `text` as in the sample. A text has `size` and `weight` (from `vz.css`: title 22/700, subtitle 13/400, column 12.5/600 upper case, name 15.5/600 (14.5 when the whole run is mono), line 13/400, label 13/400, zone 13/600, badge number 12.5/700) and `runs` of `{text, mono}`. Path `role` is `arrow`, `leader` or `legend`. Keys are `box:<id>`, `zone:<i>`, `edge:<from>-><to>#<n>`, or null.

## Review focus

1. A file on a top part with a detail map but on no sub-part: lit at top, detail lights nothing and says "On no sub-part" (J: `AppMapFileTest`).
2. A worktree checkout, where `.git` is a file: the remote is still found (J: `AppMapStoreTest`).
3. A `map.json` that is malformed or from a newer `version`: the overlay shows the "could not be read" line, never an exception (J: `AppMapFileTest.rejectsUnknownVersion`, `rejectsBrokenJson`).
4. A spec that uses every `map_svg` feature: no shape lost in conversion; an unknown element fails the build (P: `test_convert.py`).
5. A repo with untracked or ignored files: `check` counts only `git ls-files` (P: `test_build.py`).

## Batch P: the skill and the build (Python)

**Files:**
- Create: `skills/app_map/__init__.py`, `paths.py`, `facts.py`, `convert.py`, `app_map.py`, `SKILL.md`
- Create tests: `skills/app_map/tests/__init__.py`, `test_paths.py`, `test_facts.py`, `test_convert.py`, `test_build.py`
- Modify: `.claude-plugin/marketplace.json` (add `./skills/app_map` to `claude-ide-review`, one sentence in its description saying `/app-map` draws a map of the application for the IntelliJ key and needs no daemon)
- Modify: `CLAUDE.md` (one short paragraph: what app map is, where its files live, the shared `match_cases.json` contract)

**Interfaces produced:**
- `paths.matches(pattern: str, path: str) -> bool`; `paths.last_match(rules: list[str], path: str) -> int | None`
- `facts.gather(repo: Path) -> dict` with keys `build` (`"gradle" | "maven" | "folders"`), `modules` (list of `{name, dir, files, packages: {pkgdir: count}}`), `edges` (list of `{from, to, config, test}`, from = provider, to = user), `codeowners` (`{file, rules: [{pattern, owners}], teams, skipped_sections}` or null)
- `convert.svg_to_drawing(svg: str) -> dict` (`{width, height, shapes}`); raises `ValueError` naming the element or class it does not know
- `app_map.main(argv) -> int`, commands `facts <repo>`, `check <name> [--repo DIR]`, `build <name> [--repo DIR]`; `check` and `build` print a JSON report; `build` writes `map.json`, `top.svg` and `<part>.svg` for each detail

Steps:

- [ ] **P1: Tests first.** Write all four test files:
  - `test_paths.py`: every case in `match_cases.json` through `matches`, every `last_match_wins` through `last_match`.
  - `test_facts.py`: build a temp Gradle repo (`settings.gradle` including `:core`, `:orders`, `:web`; `orders/build.gradle` with `implementation project(':core')` and `testImplementation project(":web")`; `web/build.gradle.kts` with `implementation(projects.orders)`), `git init` and add files; assert modules, file counts, and edges `core→orders (implementation, test false)`, `web→orders (testImplementation, test true)`, `orders→web (implementation, test false)`. Same for a temp Maven repo with two sibling modules and a `test`-scope dependency. A `.github/CODEOWNERS` with a `[Section]` line: parsed rules, teams, `skipped_sections == 1`.
  - `test_convert.py`: render with `map_svg.render(spec, "m", keyed=True)` a spec with a title, subtitle, columns, row labels, a zone, a box with lines and a child, a `code` span, every tone, a labelled arrow, a dashed arrow, an arrow with a badge (`n`) and a legend; assert the number of shapes equals the number of drawn SVG elements, each box key appears on a `rect`, the arrow has `arrow: true` and its label and badge carry its `edge:` key, mono runs exist; an SVG with an `<ellipse>` raises `ValueError`.
  - `test_build.py`: with `APP_MAP_HOME` in a temp folder and a temp git repo of the `acme/shop` layout from `sample_map.json`, write a `source.json`; `check` reports unmapped files and empty parts and ignores an untracked file; `build` refuses a part id with no box and a duplicate part id across maps; a good build writes `map.json` whose `parts`, `details`, `owners` (from a CODEOWNERS file) and `drawings.top.shapes` match expectations, and whose shape kinds and fields are exactly those of `sample_map.json`.
- [ ] **P2: Run them:** `uv run -q --with-requirements requirements-test.txt python -m pytest skills/app_map -q` → all fail (modules missing).
- [ ] **P3: Implement** `paths.py`, `facts.py`, `convert.py`, `app_map.py` to the interfaces above and the spec's "The build" section. `check` and `build` find the repo by `--repo`, else the first existing folder in `match.folders`, else fail with one line. `owners` uses the CODEOWNERS file of that repo.
- [ ] **P4: Write `SKILL.md`** from the spec's "The skill" section (frontmatter `name: app-map`, a description that names "map of the application", "where a file belongs", "IntelliJ"). Commands go through `claude-annotate app_map.app_map ...`. It holds the design rules for a good map (12 to 25 parts, columns as layers, provider → user arrows, the legend saying so, detail maps for parts over about 800 files or split by CODEOWNERS, non-test edges only) and the update flow.
- [ ] **P5: Run the app_map tests:** same command → all pass. Then the whole suite once: `uv run -q --with-requirements requirements-test.txt python -m pytest skills fleet/tests -q` → green.
- [ ] **P6: Commit** by path: `git add skills/app_map .claude-plugin/marketplace.json CLAUDE.md && git commit -m "app-map: a skill that builds a map of an application for the IntelliJ key"`

## Batch J: the IntelliJ part (Java)

**Files (all under `ide-plugin/src/main/java/com/petros/ireview/`):**
- Create: `AppMapPaths.java`, `AppMapFile.java`, `AppMapStore.java`, `CodeOwners.java`, `AppMapCanvas.java`, `AppMapOverlay.java`, `AppMapActions.java`
- Modify: `plugin.xml` (action `com.petros.ireview.AppMapShow`, text "App Map: Show", `alt M` on both Mac keymaps), `ShortcutCatalog.java`
- Tests (`ide-plugin/src/test/java/com/petros/ireview/`): `AppMapPathsTest`, `AppMapFileTest`, `AppMapStoreTest`, `CodeOwnersTest`, `AppMapCanvasTest`; `ShortcutCatalogTest` must stay green

**Interfaces produced:**
- `AppMapPaths.matches(String pattern, String path) -> boolean`; `AppMapPaths.lastMatch(List<String> rules, String path) -> int` (-1 for none)
- `AppMapFile.read(Path mapJson) -> AppMapFile` throws `AppMapFile.Unreadable` (message is the reason); `Place place(String repoRelPath)` where `record Place(String part, String subPart, boolean hasDetail)` (`part` null when on no part); `Drawing drawing(String id)` ("top" or a part id); `List<Owner> owners(String partId)`; `String builtAt()`; `Set<String> detailIds()`
- `AppMapStore(Path home)`: `Optional<Found> find(Path projectBase)` where `record Found(AppMapFile map, Path repoRoot)`; cached by `map.json` modified time; static `normaliseRemote(String url) -> String` (`git@github.com:Acme/Shop.git`, `https://user@github.com/acme/shop.git`, `ssh://git@github.com/acme/shop` all → `github.com/acme/shop`)
- `CodeOwners.at(Path repoRoot) -> CodeOwners` (empty when no file); `List<String> owners(String repoRelPath)`
- `AppMapCanvas.paint(Graphics2D g, Drawing d, Rectangle area, double maxScale, String litPart, Palette p)`; `AppMapCanvas.keyAt(Drawing d, Rectangle area, double maxScale, Point p) -> String` (the `box:` key under a point, for clicks)

Steps:

- [ ] **J1: Tests first.**
  - `AppMapPathsTest`: reads `../skills/app_map/tests/match_cases.json` (path relative to `ide-plugin/`), runs every case and every `last_match_wins` entry.
  - `AppMapFileTest` on `sample_map.json`: `svc/src/main/java/com/acme/svc/orders/A.java` → part `orders`, no detail; `svc/src/main/java/com/acme/svc/api/Api.java` → part `svc`, sub-part `svc-api`; `svc/src/main/java/com/acme/svc/util/U.java` → part `svc`, sub-part null, `hasDetail` true; `lib/x.java` → part null. `owners("svc")` first team `@acme/core` with 120. `rejectsUnknownVersion` (version 2) and `rejectsBrokenJson` throw `Unreadable`.
  - `AppMapStoreTest`: temp home with the sample as `shop/map.json`; a temp repo whose `.git/config` has origin `git@github.com:Acme/Shop.git` is found, and `repoRoot` is that folder for a project base one level inside it; a worktree whose `.git` file points at `gitdir: <common>/.git/worktrees/w` with `commondir` `../..` is found; no remote and no folder match → empty; two matching maps → the newer `map.json` wins.
  - `CodeOwnersTest`: a `.github/CODEOWNERS` with a comment, a blank line, `/svc/ @acme/core` then `/svc/src/**/java/com/acme/svc/orders/** @acme/orders @acme/lead` and a `[Section]` line: the orders file gives both owners, a billing file `@acme/core`, `lib/x` none.
  - `AppMapCanvasTest`: paint the sample's top drawing into a 1200×600 `BufferedImage` with `litPart` `orders`; the pixel at the centre of `box:orders` (scaled) has the palette's accent fill, the centre of `box:web` does not; `keyAt` at the centre of `box:web` returns `box:web` and at an empty corner null.
- [ ] **J2: Run:** `cd ide-plugin && ./gradlew test` → the new tests fail to compile.
- [ ] **J3: Implement** the logic classes, then `AppMapCanvas` (tones and roles to a `Palette` record with light and dark values built from `JBColor` in the overlay and from plain colours in tests; dimmed shapes at 35% alpha; lit box accent fill and 2.5 px border; lit arrows in accent; arrowhead a filled triangle 7 px long on the last segment; text in the IDE UI font, mono runs in JetBrains Mono, sizes times the scale), then `AppMapOverlay` (layered pane component per the spec, header row, drawing, footer buttons Back, Owners, Close with icon and word; owners layer band and legend "Owners as of <date>"; the messages "No app map for this project. Run /app-map in Claude Code in this repo.", "The app map could not be read: <reason>. Run /app-map to rebuild it.", "On no sub-part"), then `AppMapActions` (tap under 300 ms stays open; held closes on release of `alt` or `M`; Escape, `alt M` again, a click outside the drawing, or Close closes; Enter or a click on a part with a detail opens it; Backspace or Back returns). Register the action in `plugin.xml` and `ShortcutCatalog`.
- [ ] **J4: Run:** `cd ide-plugin && ./gradlew test` → all pass, `ShortcutCatalogTest` included. Do not run `./reload`.
- [ ] **J5: Commit** by path: `git add ide-plugin/src && git commit -m "ide-plugin: alt M shows the app map over the IDE with the open file's part lit"`
