# Editing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The user opens any section and edits its markdown in place, with the dashboard's CodeMirror editor (Live, Source and Split views). What they save is final and byte-exact. The next round tells Claude exactly what changed. The user's words are marked as theirs and kept by Claude. A section open for editing is held, so Claude cannot write it.

**Architecture:**
- **webcompanion:** `PUT /s/{sid}/items/<anchor>` honours `If-Match: <version>`. It returns `412 {version}` on a mismatch, and its 200 returns the new version.
- **Editor bundle:** CodeMirror plus the dashboard's three framework-free editor files (copied and lightly adapted) are bundled once with esbuild into `static/vendor/editor.min.js`. It is loaded lazily, and exposes `window.AnnotateEditor.mount(...)`.
- **`edit.js`:** opens a section's card as the editor, saves with `If-Match`, handles the conflict prompt, holds the section through the `__holds__` item, records `mine` anchors, and adds an `edit` mark to the round.
- **`push.py`:** refuses to overwrite a held section and keeps the reader's version.
- **Claude's rules:** `handling-events.md` gains the `edit` reaction and the `mine` rule.

**Tech Stack:**
- Vanilla JS page and a Python stdlib daemon.
- CodeMirror 6 (pinned to the dashboard's installed versions), esbuild 0.25.12 (used from the dashboard's `node_modules`), Node 24 for the build only.
- pytest with Playwright.

**Spec:** `docs/superpowers/specs/2026-10-01-editing-design.md`. Mockups: https://claude.ai/artifact/8Jb1V8aukqCZMBQdgvUNGT

## Global Constraints

- The user's edit is final. The saved markdown is exactly the editor's text, never re-serialised. Claude never rewords a passage the user wrote unless a later reaction on those exact words asks it to.
- One section at a time (A1). It is edited in place inside its card, with no layout shift: the card's top and width stay unchanged.
- Views: Live (the default), Source and Split. Keys: `⌘S` save, `⌘/` toggle Live/Source, `Esc` Done, `⌘B` `⌘I` `⌘E` `⌘K` as in the dashboard. History is on.
- Ways in: `e` on the j/k-focused section with nothing selected, or ✎ **Edit** in the selection menu through `AnnotateSelection.registerAction`, which places the cursor at the start of the selected words. On a whole-section target the cursor goes to the start.
- The edit bar:
  - **State dot:** accent normally, orange when dirty.
  - **State text:** `Editing` / `Unsaved changes` / `Saving…`.
  - **View switch:** Live / Source / Split.
  - **Hint:** `⌘/ live ⇄ source · ⌘S save · esc done`.
  - **Buttons:** **Discard** (which confirms inside the bar: `Discard your changes? Discard · Keep editing`) and **Done**.
  - No browser dialogs.
- **Save:** `PUT items/<block_id>` with `If-Match: <version the editor opened at>`. The body is the stored block body with `markdown` and `mine` replaced. On `412`, the bar becomes `This section changed while you were editing. Nothing has been overwritten.` with **Show what changed**, **Take theirs** and **Keep mine**.
- **`mine`:** text anchors (`selected_text`, `prefix`, `suffix`, using `AnnotateAnchors`' 32-character context) for every run the user inserted or changed. They come from a word-level diff of the text before and after. Earlier `mine` anchors that still resolve are kept. They are painted with the Highlight registry `annotate-mine` (a quiet green rule), and the card title shows the `✎ your words` badge.
- **`edit` round mark:** `{scope: "block", kind: "edit", block_id, before, after}`, with full markdown before and after. Two edits before a submit merge, keeping the earliest `before` and the latest `after`. The dock row shows `✎` with struck-out and added words.
- **Holds:** the `__holds__` item is `{block_id: {opened_at, heartbeat_at}}` (epoch seconds).
  - The page writes it on open, refreshes `heartbeat_at` every 60 s, and removes the entry on close. On `pagehide` it removes the entry with `fetch(..., {keepalive: true})`.
  - A hold whose `heartbeat_at` is older than 30 minutes is ignored by everyone.
  - `push.py` keeps the held block's stored body instead of Claude's version. It prints `held by the reader: <ids> — kept their version; fold your change into the next round` to stderr and still exits 0.
- **Not available:**
  - Read-only pages have no editing.
  - A section of kind choice, sequence, diagram, flowchart or mockup is not editable. ✎ is absent and `e` shows `This section can't be edited as text`.
  - While a round is in flight (`WebCompanion.isBusy` / the page lock), `e` and ✎ are disabled with `Claude is working — edit when it finishes`.
- **Errors:**

  | Situation | Shown |
  |-----------|-------|
  | Bundle failed to load | `The editor could not load (<status>)` |
  | Save failed | `Not saved — <reason>` with Retry, text kept |
  | Section deleted while open | `This section was removed. Copy your text before closing` with Copy |
  | Over 2 MB | The daemon's 400 message |

- The editor bundle is built reproducibly. The CodeMirror versions are pinned exactly to the dashboard's. The bundle's first line carries `/* annotate-editor <sha256 of the source files> */`, and a test checks that hash against the sources.
- Commit messages are one line, with no body and no trailers.
- **Test commands:**
  - claude-annotate: `uv run -q --with pytest --with pytest-xdist --with playwright python -m pytest skills -q`
  - webcompanion: `uv run -q --with pytest --with playwright --with-editable . python -m pytest tests -q -p no:cacheprovider`

**Execution order:** Task 1 (webcompanion) is reviewed, merged, pushed and deployed (`pipx install --force ~/projects/webcompanion && webcompanion install-service`) before Task 4 starts, because Tasks 4–6's browser tests run against the locally installed daemon and need `If-Match` and the PUT's returned version. Tasks 2 and 3 do not depend on it.

## Review Focus

1. **A Claude rewrite arrives while the editor is open.** The re-render must not destroy the editor or the user's text. Pinned in Task 4: the reconcile guard, plus the 412 path.
2. **Byte-exactness.** Trailing spaces, hard-wrapped lines, tables, fences, CRLF pasted in, and a final newline or the lack of one must all survive a save unchanged. Pinned in Tasks 2 and 4.
3. **The page closes mid-edit.** The hold must be released, or expire, and the text must not be silently lost (`beforeunload` warns). Pinned in Task 6.
4. **`mine` after Claude rewrites around the user's words.** Anchors must still resolve. If Claude moved them, the green rule follows the words. If Claude deleted them against the rule, nothing crashes. Pinned in Task 5.
5. **Two tabs open on the same page.** The second tab must not open an editor on a section the first holds: it shows `Being edited in another tab`. Pinned in Task 6.

In `items.py`, add a lock-guarded compare-and-put. Reuse the lock file `versions.derive_versions` already uses (`.versions.json.lock` in the items dir) so the version read and the write are atomic with respect to every other version derivation:

```python
class VersionMismatch(Exception):
    def __init__(self, current: int):
        super().__init__(f"version is {current}")
        self.current = current


def put_if(items_dir, anchor, body, expected=None) -> int:
    """Write `body` under `anchor` when its current version is `expected`
    (None skips the check). Returns the new version. The read, the write and
    the version derivation happen under the one lock versions.py uses."""
    import fcntl
    items_dir = Path(items_dir)
    items_dir.mkdir(parents=True, exist_ok=True)
    lock_path = items_dir / ".versions.json.lock"   # match versions.py exactly
    with open(lock_path, "a+") as lock:
        fcntl.flock(lock, fcntl.LOCK_EX)
        try:
            current = snapshot(items_dir).get(anchor, {}).get("version", 0)
            if expected is not None and current != expected:
                raise VersionMismatch(current)
            put(items_dir, anchor, body)
            return snapshot(items_dir)[anchor]["version"]
        finally:
            fcntl.flock(lock, fcntl.LOCK_UN)
```

Read `versions.derive_versions` first. If it already takes the same lock inside `snapshot()`, a nested `flock` on the same file from the same process would deadlock. In that case factor the lock into a context manager in `versions.py` and use a re-entrant pattern, or call the unlocked internals under one lock. Write the test for the race (above) before deciding, and record the choice in the report.

In `server.py`, `_put_item`:

HELD_STALE_S = 1800

def held_blocks(prev, now):
    holds = (prev.get("__holds__") or {}) if isinstance(prev.get("__holds__"), dict) else {}
    out = set()
    for bid, h in holds.items():
        try:
            if now - int(h.get("heartbeat_at", 0)) <= HELD_STALE_S:
                out.add(bid)
        except (TypeError, ValueError, AttributeError):

    return out

held = held_blocks(prev, int(time.time())) & set(items) & set(prev)
