# Shot list

Two recordings are missing from `README.md`. Each is marked there with a
`<!-- SCREENSHOT: … -->` comment — replace the comment with
`![alt text](docs/img/<name>)` once the file exists.

Keep GIFs under about 5 MB; GitHub will not render larger ones inline.

## hero.gif

The whole point in one loop. Start with a long Claude answer already rendered in
the browser. The cursor moves to one block, clicks, types a short correction,
submits — and that block visibly changes while the rest of the page holds still.
About 8 seconds. Do not show the terminal; the browser is the product here.

## comment-flow.gif

Slower and closer. Frame only two or three blocks, at a font size that is
actually readable in a GitHub README, so the in-place patch is unmistakable
rather than merely implied. About 6 seconds.

## Capture notes

- Light theme reads better in a README, especially on GitHub mobile.
- Use real content, not placeholder text. A plan someone might genuinely ask
  for — the realism is doing persuasive work.
- Crop out session paths, hostnames, and anything else identifying.
- Record at 2× and scale down; a retina capture scaled to 50% looks far
  sharper than a native-resolution one.
